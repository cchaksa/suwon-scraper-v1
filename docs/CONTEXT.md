# CONTEXT.md

이 문서는 작업 컨텍스트 문서를 작성할 때 지켜야 할 규약이다.

## 1) 파일 생성 규칙
- 컨텍스트 문서는 `docs/` 하위에 생성한다.
- 파일명은 반드시 `{작업 이름}-context.md` 형식을 사용한다.
- 파일명은 소문자 kebab-case를 권장한다.
  - 예: `login-error-handling-context.md`

## 2) 작성 목적
- 작업의 배경, 범위, 결정사항, 검증 기준을 한 번에 파악할 수 있게 기록한다.
- 후속 작업자가 추가 질문 없이 이어서 작업할 수 있도록 근거를 남긴다.

## 3) 필수 작성 항목
- 작업 이름
- 작업 배경/문제 정의
- 목표와 비목표(Out of scope)
- 현재 상태 분석(관련 파일/흐름)
- 결정사항(선택한 방식과 이유)
- 구현 계획(단계별)
- 검증 계획(테스트/체크리스트)
- 리스크 및 롤백 포인트

## 4) 작성 원칙
- 코드/설정 파일 기준의 사실만 작성하고 추측은 분리한다.
- 경로, 명령어, API 이름은 실제 값으로 명시한다.
- 변경 범위와 비변경 범위를 명확히 구분한다.
- 문서는 한국어로 작성한다.
