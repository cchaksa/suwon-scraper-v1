# 편입생 지정과목 크롤링 컨텍스트

## 작업 이름

- `designated-courses`
- 최초 구현: GitHub 이슈 `#21`.
- 응답 키 및 오류 처리 수정: GitHub 이슈 `#26`.
- 요청 조직분류코드 누락 수정: GitHub 이슈 `#28`.

## 작업 배경/문제 정의

- #21에서 편입생 지정과목을 `scrapeJob` 결과와 S3 원문에 추가했다.
- 2026-09-27 포털에는 지정과목 3개가 있지만 개발 서버에는 빈 목록이 저장된 문제를 확인했다.
- 실제 포털 응답은 `precpSbjtList`인데, 크롤러와 테스트는 `listPrecpSbjt`를 사용하고 키 누락을 빈 배열로 정규화했다.
- 백엔드는 성공 콜백의 `result_s3_key`로 원문을 읽으므로, 응답 형식 오류를 성공 결과로 저장하지 않아야 한다.
- #28에서 사용자가 같은 로그인 세션으로 비교한 결과, 학번만 전송하면 HTTP 200과 빈 배열이 반환되지만 `orgClsCd: "20"`을 추가하면 가족관계·인간행동과사회환경·아동권리와복지가 반환됐다. 응답 형식 검증으로 감지할 수 없는 조회 조건 누락이다.

## 목표와 비목표

### 목표

- 편입생 지정과목 API를 크롤링한다.
- `student.enscDvcd === "2"`인 경우에만 API를 호출한다.
- 모든 성공 결과에서 `designatedCourses` 배열을 보장한다.
- 명시적인 `precpSbjtList: []`만 정상 빈 목록으로 처리하고, 응답 형식 오류는 전체 작업 실패로 전달한다.
- S3 결과 계약과 테스트를 함께 갱신한다.

### 비목표

- 지정과목을 `semesters[].courses`에 병합하지 않는다.
- 지정과목 이수 여부를 별도로 판정하지 않는다.
- 백엔드의 S3 조회 로직은 변경하지 않는다.
- 외국어 인증 필드의 별도 회귀 테스트는 이슈 범위에 포함하지 않는다.

## 현재 상태 분석

- `src/services/scrapeJob.ts`는 로그인 후 학생·수강·성적 크롤러를 병렬 호출한다.
- `src/services/resultStorage.ts`는 `scrapeJob` 결과를 별도 가공 없이 JSON 직렬화해 S3에 저장한다.
- 편입생 포털 화면에서 `POST /precpSbjt/listPrecpSbjt.do` 호출을 확인했다.
- 지정과목 그리드의 데이터 필드는 `orgClsCd`, `subjtCd`, `subjtNm`, `point`, `precpResnCd`, `cretGainYear`, `cretSmrNm`, `sno`다.
- 현재 작업 트리의 `.gitignore` 변경은 사용자 소유 변경이므로 이 작업에서 수정하거나 커밋하지 않는다.

## 결정사항

1. S3 결과의 최상위 필드명은 `designatedCourses`로 정한다.
2. 포털 응답 배열 키는 실제 응답에서 확인한 `precpSbjtList`를 사용한다. 요청 URL의 `listPrecpSbjt.do`는 유지한다.
3. 비편입생은 API를 호출하지 않고 `designatedCourses: []`를 반환한다.
4. 편입생의 명시적인 빈 배열만 정상 처리한다. 키 누락·null·배열이 아닌 값·JSON 구문 오류는 `PORTAL_RESPONSE_SCHEMA_MISMATCH`, `retryable: false`로 실패 처리한다.
5. 편입생 API가 비정상 HTTP 상태를 반환하면 다른 핵심 크롤러와 동일하게 작업을 실패시킨다.
6. 학생·수강·성적 요청의 기존 병렬성을 유지하되 지정과목 요청은 학생 정보 Promise가 편입생으로 판정된 뒤 시작한다.
7. 지정과목은 수강·성적과 의미가 다르므로 학기 병합 결과에 넣지 않는다.
8. 형식 오류 시 S3 결과를 저장하거나 성공 콜백을 보내지 않고 기존 실패 콜백 경로를 사용한다. 콜백 자체의 전송 재시도 정책은 유지한다.
9. JSON 구문 오류의 원문은 오류 메시지에 넣지 않는다. 본문 읽기 중 통신 오류는 기존 분류와 재시도 정책을 유지한다.
10. 지정과목 요청 본문은 `{ sno: username, orgClsCd: "20" }`으로 고정하고 요청 계약 테스트로 누락을 방지한다. 실제 지정과목이 없는 정상 빈 배열은 계속 허용한다.

## 구현 계획

1. 크롤러가 `precpSbjtList`를 읽고 응답 형식을 검증하도록 수정한다.
2. 워커 오류 코드에 `PORTAL_RESPONSE_SCHEMA_MISMATCH`를 추가한다.
3. 크롤러·조합 로직·오류 분류·워커의 성공 저장 및 실패 콜백 경로를 회귀 테스트한다.
4. README와 기존 지정과목 설계의 응답 계약을 정정한다. #21의 과거 구현 계획에는 현행 계약 링크를 남긴다.

## 검증 계획

- 정상 응답에서 지정과목 배열과 필드가 유지되는지 확인한다.
- 요청 본문에 학번과 문자열 조직분류코드 `"20"`이 함께 포함되는지 확인한다.
- `precpSbjtList: []`만 정상 빈 목록이고, 잘못된 키·누락·null·타입 오류·JSON 구문 오류는 형식 오류인지 확인한다.
- 편입생은 지정과목 API를 한 번 호출하고 비편입생은 호출하지 않는지 확인한다.
- 지정과목 API 비정상 상태가 오류로 전파되는지 확인한다.
- 저장 대상으로 전달되는 결과에 `designatedCourses`가 항상 존재하는지 확인한다.
- 형식 오류는 S3 저장 없이 오류 코드와 `retryable: false`를 포함한 실패 콜백으로 전달되는지 확인한다.
- 정상 응답의 추가 필드를 보존하고, 본문 읽기 중 timeout·통신 오류의 재시도 정책을 유지하는지 확인한다.
- `yarn build`와 `yarn test`를 실행한다.

## 리스크 및 롤백 포인트

- `enscDvcd` 코드 계약이 바뀌면 조건부 호출이 누락될 수 있으므로 코드 `"2"`를 테스트로 고정한다.
- 지정과목 API 장애나 응답 형식 오류는 편입생 작업 전체를 실패시킨다. 불완전한 빈 목록을 성공 결과로 저장하지 않는다.
- 수정 전 워커로 롤백하면 지정과목이 다시 빈 목록으로 저장될 수 있으므로 재동기화 진행 여부도 함께 판단해야 한다.

## 구현 결과

- `DesignatedCourseDTO`와 `scrapeDesignatedCourses`를 추가했다.
- `scrapeAuthenticatedData`가 편입생에게만 지정과목 API를 호출한다.
- 모든 성공 결과와 S3 저장 payload가 `designatedCourses` 배열을 포함한다.
- README와 `AGENTS.md`를 최종 결과 계약에 맞게 동기화했다.
- #26에서 실제 응답 키와 명시적인 형식 오류를 적용했다. 기존 조합 로직과 워커의 실패 경로를 그대로 활용한다.
- #28에서 요청 본문에 `orgClsCd: "20"`을 추가하고, 요청 계약 테스트와 문서를 보완했다.
